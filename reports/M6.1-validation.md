# M6.1 Validation Report

Date: 2026-08-18
Status: **PASS, approved 2026-08-19**

## 中文审阅摘要

M6.1 补全了 DSH Web Workspace 到 Three.js Editor 的产品入口：

```text
用户在 DSH Web 选择本地 Three.js 工程
  -> Session.header.cwd
  -> dsh-mcp-apps request _meta
  -> threejs-editor-mcp 动态注册 Linked Workspace
  -> opaque projectId
  -> 同一 Chat 卡片内打开 Editor
```

用户不再需要创建临时目录、复制工程、初始化 Git，或通过 Server 启动参数预注册
游戏目录。`--workspace` 仍只用于自动化测试、固定部署和没有 DSH Session 的 MCP
客户端。

完整用户操作见 [`../docs/USER-OPERATIONS.md`](../docs/USER-OPERATIONS.md)。

## 实现

`dsh-mcp-apps` 增加显式关闭的 `forwardWorkspace` 配置。只有可信本地 stdio
Server 设置 `forwardWorkspace: true` 后，Host 才会把调用 Agent 不可变的
`session.header.cwd` 写入 `tools/call` request metadata：

```text
ai.deepseek.dsh/workspace
```

远程 HTTP Server、App 发起的调用、模型可见 tool 参数和结果都不会获得该路径。

`threejs-editor-mcp` 的 `open_editor.projectId` 现在可选。省略时，Server 只接受
上述可信 metadata，解析真实目录并生成稳定的：

```text
workspace-<sha256>
```

后续 model tools 和 app-only tools 继续只使用 opaque `projectId`。
Session 动态注册项不进入全局 `list_projects`。
